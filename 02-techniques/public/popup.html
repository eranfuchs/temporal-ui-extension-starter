Per-row questions these make requests

Everything above reads answers the page was already fetching. These two ask Temporal questions of their own — one request per running row each, so a list of closed workflows costs nothing. Answers are cached for 30s, four requests run at a time, and a rate limit backs off instead of retrying. Closed rows are never asked about: their answers cannot change.

The badge shows the attempt count, the activity type and the next retry time. It deliberately does not read the failure message: that is application data, and nothing in this extension reads any. Everything on screen here comes from event metadata — no workflow input, result or failure is decoded, which is why there is no codec-server box. That is stage 03, the payload stage, which is not written yet.

Payloads

Adds an In and an Out button to every row — two independent questions, not one combined panel. Hover either — or focus it with the keyboard — to read that workflow's input or its result. Nothing is requested until you open one: a page of a hundred rows costs no requests at all, and opening one costs at most one history event, so hovering only In never touches the result and vice versa. Switching this off closes the panel and forgets everything it had decoded.

Filtering

Hover a Workflow ID, Run ID, Type, Status or Task Queue cell for a ≠ button that filters the list to everything except that value — Temporal's own per-cell button only offers equals. Ctrl/Cmd-click either button — ours or Temporal's own — to add the clause to the current filter instead of replacing it. Reads only what is already on screen and makes no request of its own; a click just changes the page's own URL.

Per-row questions these make requests

These two ask Temporal questions of their own, the same way the payload buttons above do — one request per running row each, so a list of closed workflows costs nothing. Answers are cached for 30s, four requests run at a time, and a rate limit backs off instead of retrying. Closed rows are never asked about: their answers cannot change.

The badge shows the attempt count, the activity type and the next retry time. It deliberately does not read the failure message — that is a decision about what these two features read, and it still holds: everything in the column and the badge comes from event metadata. Payloads are the section above, on their own button, and the failure message arrives with them.

Codec server optional

Only needed for payloads this extension cannot read on its own — binary/encrypted above all. Plain json/plain payloads are decoded in the browser and are never sent anywhere. The request is the one the Temporal UI makes, apart from its two credential options — POST {endpoint}/decode, the namespace in X-Namespace — so a codec server that already works there needs no change unless it authenticates its callers (see below): the same URL you set under Codec Server in the Temporal UI belongs here. An empty box means no payload byte leaves this machine. When it is filled, only the payloads that cannot be read in the browser are sent, and the panel names the host it sent them to, every time.

Unlike the Temporal UI, this extension sends no credentials to a codec server — not your access token, not cookies — and cannot be made to: there is no setting for either, and the one function that can post to a codec server switches cookies off itself and refuses a credential header rather than forwarding it. The endpoint is chosen through a channel any script on the page can write to, which is not a channel to aim a credential from. So a codec server that authenticates its callers will answer 401 here and the panel will say so. Point this at one that does not, such as your own on localhost.
